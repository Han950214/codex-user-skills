# 项目交接

只在确需切换任务、账号或 Agent 时生成交接，不把交接当作普通开发步骤。

## 收集事实

1. 确认唯一仓库绝对路径；不要混入相邻仓库。
2. 只读记录 `branch`、`HEAD`、`origin` 和当前 Git 状态。清除远端 URL 中可能存在的凭据。
3. 从当前任务、规格、计划、测试输出和 Git 证据中提取当前阶段、已完成事项、未完成事项及验证限制。
4. 引用已有规格、ADR、提交或报告的路径，不重复粘贴长内容。

## 输出内容

按以下顺序写入交接材料：

- 唯一仓库路径；
- branch、HEAD、origin；
- 当前阶段和权威规格；
- 已完成事项；
- 未完成事项与明确阻塞；
- 已运行的测试及真实结果；
- Git 状态和现有用户改动；
- 当前任务的禁止事项；
- 下一阶段建议调用的 Skill，最多列必要项。

默认将完整交接文件保存到操作系统临时目录，不写入产品仓库。最终回复同时给出一段可直接复制到新任务的精简接管文本，并附完整文件路径。

## 脱敏

在写入文件和回复前移除 API Key、密码、访问 Token、Cookie、电话号码、家庭或办公地址及其他个人敏感信息。只保留继续任务所需的最小技术上下文；无法安全脱敏时改写为占位说明。

不得借交接修改代码、创建提交或执行远端操作。
