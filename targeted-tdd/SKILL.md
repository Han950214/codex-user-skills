# 定向 TDD

只在能够从公开模块接口或用户可见行为稳定观察结果时使用。

## 红 → 绿 → 重构

1. **选 seam**：确认当前项目已有的公开接口、测试入口和阶段边界。不要为了测试方便暴露私有实现、增加无调用方 wrapper 或改造产品架构。
2. **红**：写一个最小测试，使用独立的已知期望值验证一个真实行为；运行并确认它因目标行为缺失或 Bug 而失败。
3. **绿**：只实现使当前测试通过的最小产品改动；不要提前实现尚未由测试要求的能力。
4. **重构**：在保持测试绿色的前提下清理重复和命名，继续通过公开接口验证行为。
5. 对下一条行为重复一个垂直切片；不要先批量写完所有测试再批量实现。

## 测试质量

- 测试描述调用方或用户能够观察的结果，不绑定私有方法、内部调用次数或临时数据结构。
- 只在外部 API、时间、随机性、文件系统等系统边界使用替身；优先复用项目现有 fixture 和测试基础设施。
- 不写按实现算法重新计算期望值的同义反复测试。
- 没有正确 seam 时停止 TDD 分支，说明为什么现有测试无法真实覆盖该行为，并改用与任务相称的验证方式。
- 每轮记录失败命令、通过命令和相关回归结果；不安装新依赖，不扩大仓库或阶段范围。
